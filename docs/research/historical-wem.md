# 音频 ID 与内容：历史版本实测

初次研究：2026-09-21，七个年度版本、三个英雄，共 42 个 WAD。
2026-10-12 补充 Sound ID 与同年度较远、相邻补丁比较；该阶段共 48 个 WAD。

> **不能仅凭音频 ID 判断是不是同一份音频。** 内容完全相同，ID 可以改变；ID 不变，内容也可能改变。

下文原研究中的“音频 ID”指 **WEM ID**。新增的 [Sound ID 实测](#sound-id-study) 将它与 HIRC 对象 ID 分开统计。
事件名与 Event ID 的后续调查见 [事件范围的历史版本实测](historical-events.md)，最终统计数据与分析脚本说明也在该页。

## 两种容易误判的情况

- **换号，内容不变**：安妮中文 10.15 → 11.15，48 个旧 ID 全部换掉，47 份唯一 WEM 内容逐字节一致；其中一份对应两个 ID。
- **ID 不变，内容改变**：安妮中文 14.15 → 15.15，48 个同 ID 的 WEM 原始字节全部改变。

这里的“相同”指 **原始 WEM 逐字节相同**。没有做试听或转码后的波形比较，不判断重编码前后的声音是否相同。

## WEM 结构与比较范围

实际样本以 `RIFF ... WAVE` 开头，含 `fmt `、`data` 等区块；[vgmstream 的 Wwise 解析器](https://github.com/vgmstream/vgmstream/blob/master/src/meta/wwise.c)也按该结构解析。原始 WEM 可以无损复用，但不能假设它没有可变头部。

- 安妮中文 13.15 → 14.15：31 个同 ID 文件字节变化；其中 0 个 `data` 区块字节相同。
- 安妮中文 14.15 → 15.15：48 个同 ID 文件字节变化；其中 0 个 `data` 区块字节相同。
- 安妮中文 15.15 → 16.15：48 个同 ID 文件字节变化；其中 0 个 `data` 区块字节相同。

`data` 改变仍不能证明听感改变，可能涉及编码或封装。完整 WEM 摘要适用于原始字节复用，不能用来识别所有重编码后听起来相同的声音。

## 当前仓库如何保存

**实际 WEM 内容是复用依据，音频 ID 是引用信息。** 资源库将内容与索引分开保存，按内容摘要定位对象；
每个版本的 ID 关联到实际内容，不能把关系压扁为全局 `ID → 唯一文件`。

| 层次 | 保存内容 | 位置或规则 |
| --- | --- | --- |
| 内容对象 | 原始 WEM 完整字节 | `audios/_data/<摘要前两位>/<SHA-256>.wem` |
| 内容索引 | 版本、语言、实体、皮肤、WEM ID 与摘要的对应关系 | `audios/_index/<版本>/<语言>.msgpack` |
| 可见目录 | 供浏览与处理的 WEM 路径 | 通过硬链接指向内容对象，不额外复制媒体 |
| 派生结果 | WAV 与手动导出的文件 | 按转换或导出规则保存，与原始 WEM 库分开 |

在同一个资源库里，**字节完全相同的 WEM 只存一份数据**。不同版本、皮肤或 ID 可以引用同一对象，
不会因多个可见路径重复占用音频内容的磁盘空间；索引和目录项仍有少量开销。

- 同 ID 获得新内容时，记录新的摘要；不同版本分别保留实际对应关系。
- 解包仍须读取实际源文件。BIN 或 ID 没变，不能证明 WEM 内容没变。
- 共享只按完整原始字节判断，不做听感去重；独立导出的 WAV 或 WEM 副本仍会占用空间。
- 硬链接路径共享底层内容；编辑前先导出独立副本。库内链接必须位于支持硬链接的同一卷。

索引结构、写入与恢复接口见 [资源库 API](../api/library_api.md)；用户查找结果目录见 [音频文件与输出目录](../audio-and-output.md#output-folders)。

## 验证与适用范围

- 42 个 WAD 均通过 PyManifest 清单块校验；再次核对 WAD SHA-256。扫描 32,129 个条目，未解决错误为 0。
- 独立读取 WPK 原始偏移表，复核 4,015 个媒体文件名、ID、边界及实际字节；所有严格换号候选均逐字节复核。BNK 使用 DIDX/DATA 边界检查。
- 清单校验使用 PyManifest（riotmanifest 2.10.0，提交 `a8cd28d2fc72649669ef24fa7e14cea7264ca0a4`，Python 3.10）；提取使用 Python 3.13、league-tools 1.2.1、zstd 1.5.7.2。
- 7,615 个类型 4 条目用研究适配的 zstandard 0.25.0 读取连续帧并核对输出长度，全部为 TEX 纹理。此适配没有修改产品依赖或业务代码。
- 七个年度样本能证明期间发生过换号，不能定位发生在哪个具体补丁，也不能从这些 WAD 单独证明英雄全部玩法、事件逻辑或皮肤均未改动。
- 结果是 WEM 文件字节层面的证据，不以 WAD/BNK 大小或哈希变化推断音频更新；未扫描全部英雄，未验证所有未知非标准封装。
- 本次研究的清单校验不进入产品预检；产品仍仅检查资源文件存在。没有修改应用业务代码或执行产品回归测试。

原研究另保留清单、原始 WAD/WEM、完整比较 JSON、相邻版本 CSV 与执行日志。本页从研究报告整理，保留结论、统计口径与可定位的证据，不收录原始客户端文件。

## Sound ID 实测：仍然不能作为跨版本主键

2026-10-12 复用原来的 42 个 WAD，增加 11.5、11.16 三个英雄的中文 WAD，共 48 个输入。
两版构建分别为 `11.5.3613108`、`11.16.3901945`，RMAN 分别为 `338FE08ABB6D87EC`、`66C2E00089509D3F`。

| 字段 | 本次实际来源 | 作用 |
| --- | --- | --- |
| Sound ID | BNK HIRC 类型 2 的对象 ID；模型中为 `object_id` | 定位一个版本内的 Sound 对象配置 |
| WEM ID | WPK 文件名或 BNK DIDX 媒体 ID；文件源 Sound 中为 `source_id` | 定位媒体文件 |
| Event ID | HIRC Event 对象 ID | 定位事件，后续沿对象关系找到候选媒体 |
| SHA-256 | 完整原始 WEM 字节 | 判断本次原始文件内容是否相同 |

Sound 对象可复用同一个媒体；[Wwise 官方的媒体 ID 说明](https://www.audiokinetic.com/zh/public-library/2024.1.9_8920/index.html?source=Help&id=managing_media_asset_ids)
也区分对象 ShortID 与 MediaID 的作用域。本次 15,022 条 Sound 记录中，
**15,006 条文件源的 Sound ID 均与其 WEM ID 不同**，且都能关联实际媒体；其余 16 条是 Wwise Silence 源插件，不对应 WEM。
这证明本次两种字段必须区分，不能据此断言所有工程都绝不可能偶然取到相同数字。

### 当前解析器够用到什么程度

本次 332 个 BNK 使用 Wwise bank 格式 132、134、145，与游戏补丁号不是同一个版本字段。
逐项读取原始 HIRC Sound 头后，与当前 `load_hirc` / NativeHIRC 的 `object_id`、`source_id`、`stream_type` 一致，
未解决字段差异和媒体关联均为 0。更早格式可能另外包含 `uFileID`，本轮没有验证。

- 固定 [wwiser 提交](https://github.com/bnnm/wwiser/tree/08e937b649bc7007c234bbd59e34a41d5eef3b38)（v20260808），
  独立核对 19 个关键 BNK、1,809 条 Sound；原始 XML、NativeHIRC、WwiserHIRC 字段一致。
- 118 个 BNK 含内嵌媒体，7,843 次媒体引用按 DIDX/DATA 与提取 WEM 逐字节核对。不能假设所有资源都在 WPK。
- 新增 WPK 按原始偏移表、UTF-16LE 文件名、边界和字节独立核对；16 条 Silence 插件记录单独统计。
- 数据包的 `sound-summary.json` 与 `sound-verification.json` 保存完整汇总和独立核验清单。地图与其他语言未加入样本。

低层模型可以区分这两个字段；当前公开事件映射沿 Sound 收集文件 `source_id`，输出的是 WEM ID，
不能把某些变量的 `sound_ids` 名称误认为 HIRC Sound 对象 ID。当前资源库保存媒体 ID 与内容摘要，
本轮没有新增持久 Sound 索引，也没有修改产品存储格式。

参考 [lol-vo-extract 的固定版本](https://github.com/lol-archiver/lol-vo-extract/tree/90ca5df96ae9d1f0a1a4b6aff98d8004d75854f7)
同时保存 Sound 的 `id` 与媒体 `idAudio`，导出逻辑还使用双 ID 和可选的 WEM CRC32。
这些信息能描述其解包版本内的关系；本次实测不支持将任一数字提升为跨版本永久身份。
当前内容库仍需要按原始 WEM 摘要复用文件，后续事件分组用途见 [事件研究结论](historical-events.md#use-event-scope)。
